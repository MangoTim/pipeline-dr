PROD/DR MCP Pipeline

One image, built and scanned once, deployed to two sites. Every stage is a stage of the Jenkinsfile.
Jenkins on .105 (control plane)  ·  Jenkinsfile
1Checkout
git clone git://127.0.0.1:9418/ mcp-dr-pipeline.git
2Fetch the MCP source
curl -fsSL .../linux-mcp-server/ archive/6d7ca1d1....tar.gz
3Resolve the version
VERSION + date +%d%m%y -> v1.0.<DDMMYY><NN>
4Build the image
podman build --file upstream/ Containerfile --format docker
GATE
5Aqua scan
podman run ...scanner scan --local ... | grep Compliant
6Trivy scan (baseline)
podman run ...trivy image --scanners vuln --pkg-types library
7Security remediation
scripts/trivy_cve_packages.py -> Containerfile.remediated
GATE
8Trivy final scan
trivy image --exit-code 1 -> 0 HIGH / CRITICAL
9Export the artifact
podman save <image> | gzip > ....tar.gz ; sha256sum
10Deploy to BOTH sites
ansible-playbook -i inventory.ini site.yml

▼
The MCP inspects the host it is deployed on. The upstream image sets ENV container=docker, so the server refuses to run locally and must reach a host over SSH — and it reaches its own host's sshd. That is why the same bytes give a different answer on each site: the answer is the live machine's real hostname, cores, RAM and disk, read over SSH from the kernel — never a canned string.
